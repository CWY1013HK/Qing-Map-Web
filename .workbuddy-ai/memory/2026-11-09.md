# 2026-11-09

## Diagnosis only (no fix): `/atlab` is much laggier than `/`

Investigated source + profiled both pages in headless Edge via CDP at 1440x900.
No source files changed.

Findings (measured, steady state after intro):
- Normal: 2 OSD update loops, 1 main canvas (1440x900), 0 focus clouds, 0 sea underlays, 893 DOM elements.
- ATLab: 3 OSD update loops, wall canvas 3536x772 + floor canvas 1x1, 34 focus-cloud/decor OSD overlays, 1 pinned full-bleed sea underlay (3536x2400, 13 SVG patterns), 2 overlay layers + 2 province-label layers, 1414 DOM elements; `#atlab` has `transform: scale(0.2837)`.
- rAF callbacks / 5s: 628 (normal) vs 1527 (atlab). Extra loops attributed to `src/viewer/seaUnderlay.ts` `tickDrift` (300) and `src/viewer/focusMode.ts` `tick` (300), plus the 3rd OSD viewer.
- Main thread busy: 5.3% vs 10.7%; LayoutCount 0 vs 300 (one forced layout per frame, from `viewer.updateOverlay` on 34 sprites -> OSD `forceRedraw`).
- 4s timeline: GPUTask 186ms -> 443ms, Paint 26ms -> 69ms, RasterTask 9ms -> 28ms, Layerize 71ms -> 172ms.

Root causes:
1. `bootFloor.ts` permanently runs `startSeaUnderlay(..., {lite:true, host})` WITHOUT `static:true` -> `applyDrift` rewrites `patternTransform` on 13 SVG patterns every frame, re-rastering an 8.5M-px full-bleed SVG floor.
2. `startFocusClouds` on floor runs forever with 14 clouds + 20 fuchuan; each `viewer.updateOverlay` forces a full OSD redraw and a layout every frame.
3. `#atlab` CSS `scale()` does not change `clientWidth`; OSD `autoResize` still allocates/renders at 3536x772 (and DPR multiplies it), ~12x more pixels than actually displayed. Everything under the scaled root must be re-rastered then downscaled each frame.
4. Everything is duplicated on a 2nd viewer (overlays, province labels, 3rd OSD loop); intro also spawns 76 veil clouds vs 52 with drop-shadow filters.
5. During tours/focus mode the wall gets a second sea underlay + 24 clouds + 15 fuchuan on top.

Likely fix directions (NOT applied): pass `static: true` for floor sea underlay (or throttle drift), replace per-frame OSD `updateOverlay` sprites with one CSS/DOM animation layer (or lower FPS), keep the floor viewer's update loop asleep, and make the wall OSD aware of the fit scale. User asked to diagnose first.
